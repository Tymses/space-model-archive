# SPACEMESHER (SPACEMESHER)

A minimal, source-linked archive for discovering space-related 3D models and preparing them for 3D printing.

## Project principles

- Preserve and document real-world scale wherever source data supports it.
- Link to original model sources instead of mirroring files by default.
- Show provenance and licence information alongside each model.
- Help users assess whether a model fits a selected printer's build volume.
- Support scale calculations and geometry-based fit checks where the source preview exposes measurable geometry.
- Do not integrate a slicer. Users prepare and slice files in their own software.

## Current interface

- Five collections: Spacecraft, Planetary features, Asteroids, comets & meteorites, Moons, and Height maps. The first four are collections of physical objects and their model files; Height Maps is visually separated as a terrain-data and generation collection.
- Collection search with source and type filters.
- NASA 3D Resources is indexed from its complete public `3D Models` and `3D Printing` Git tree: 650 individual files (257 GLB, 342 STL, 27 7Z packages, 13 BLEND, 4 3DS, 4 LWO, 2 FBX and 1 VSP3) in the 2026-11-24 snapshot, each with a direct original-file link. 29 planetary STL records are also cross-listed in Height Maps.
- Space Radar is indexed from its public repository: all 203 models in its official GLB catalogue plus 108 additional GLB map assets (including 18 asteroid/comet/dwarf-planet shape models and 11 natural-satellite shape models). File sizes and per-model attribution notes are stored in `data/spaceradar-model-index.json`.
- NASA/JPL Radar Astronomy contributes 19 individually indexed direct OBJ downloads from its radar-derived asteroid shape-model list, stored in `data/jpl-asteroid-index.json`.
- The 3D Asteroid Catalogue reports 1,635 asteroids, 5 comets, 2 dwarf planets, 37 moons, 3,079 shape models and 54 textures. SPACEMESHER includes a curated selection of 256 numbered asteroids in `data/asteroid-curated-index.json`; each record opens the original asteroid detail page, where available OBJ/PLY model downloads and model attribution are listed. These are verified source-page download routes, not direct file URLs; SPACEMESHER does not invent download filenames or sizes. The complete 1,635-object source index remains linked separately. The five comet detail pages, Ceres and Pluto, and the full 37-moon listing are also linked. The 67P page lists 12 variants (each OBJ + PLY); the other four comets list one OBJ + PLY each. Ceres lists four variants (eight OBJ/PLY files); Pluto lists one OBJ/PLY pair and five textures.
- NASA PDS source records are linked for all five comets. The Stooke PDS4 archive (252 kB; contains Halley plus other small-body models) and the Tempel 1 PDS archive (3.0 MB) are indexed as downloadable ZIP packages. Other PDS comet datasets remain linked to their official dataset pages where a verified archive download URL could not be obtained.
- NASA Astromaterials 3D now includes 17 individually linked Antarctic meteorite sample detail pages. Each page provides full- and low-resolution textured OBJ ZIP downloads. The page-specific ZIP endpoints are generated by the NASA web application and are not yet separately recorded as direct file URLs. NASA says these model downloads are public domain and requests NASA attribution.
- The Zenodo meteoroid/rock-fragment dataset is indexed as three archive records: L01.zip (199.8 MB) and L02.zip (197.6 MB), both containing NWA 869 meteorite fragments, and T01.zip (56.8 MB), containing terrestrial Kunětická hora rock fragments. Together the dataset reports 868 OBJ meshes. SPACEMESHER links to the Zenodo file record for these three ZIPs; it does not expand the ZIP contents into 868 separate site records.
- The small-bodies source collection now links each of the five comets in the 3D Asteroid Catalogue individually: 67P/Churyumov-Gerasimenko, 1P/Halley, 103P/Hartley 2, 9P/Tempel 1 and 81P/Wild 2. Their source pages offer OBJ and PLY shape-model downloads, with multiple model variants for 67P. These are catalogue-page links, not yet direct-file records inside SPACEMESHER.
- Meteorite sources now include NASA Astromaterials 3D's sample catalogue and Explorer, its NASA Johnson Space Center Sketchfab collection (43 published models), and a Zenodo dataset of 868 OBJ fragment meshes. The Zenodo dataset comprises two NWA 869 meteorite-fragment sets and one terrestrial-rock-fragment set; it is not 868 distinct meteorite specimens. NASA Astromaterials 3D provides sample-specific high- and low-resolution OBJ ZIP downloads and states that its data is public domain with NASA credit requested.
- Collection pages visually separate individual downloadable model files from source catalogues, scientific data, viewers and on-demand generators. Source cards are explicitly classified by type. Terrain Print and NASA Solar System Treks are generators, not fixed model libraries.
- A verified native STEP assembly for the ESA ExoMy rover is listed separately; its source notes warn that purchased-component geometry may have different reuse rights.
- GLB models have an in-browser 3D preview; STL files have direct downloads and source attribution. The NASA Phobos model page embeds NASA/JPL interactive 3D content and links to glTF and USDZ downloads. The NASA index is stored at `data/nasa-model-index.json` and can be regenerated from the public Git tree. The Space Radar index is stored at `data/spaceradar-model-index.json` and can be rebuilt from its `site/model/models.json`, `site/models/` files and `CREDITS.md`. The JPL radar index is stored at `data/jpl-asteroid-index.json`.
- NASA terrain and asteroid print files are discoverable in the planetary, small-bodies and height-map collections. The Moons collection includes 11 individual Space Radar Saturn-moon GLBs, two NASA Moon STL files, the official NASA/JPL Phobos 3D-model resource page (glTF and USDZ downloads), the NASA Solar System Treks moon portal catalogue, and the NASA PDS satellite shape-model dataset. The Treks portal catalogue covers Phobos, Io, Europa, Ganymede, Callisto, Titan, Earth's Moon and Icy Moons Treks; it is kept distinct from individual downloadable files.
- NASA Solar System Treks is indexed as a 3D surface-data and print portal catalogue at https://trek.nasa.gov/#. Users explore mission-derived data and can export selected terrain; this is not represented as a static model file.
- Verified real-world longest-axis dimensions are stored separately in `data/real-world-dimensions.json` and automatically applied to matching NASA, Space Radar, JPL and curated asteroid records. Duplicate catalogue entries for the same numbered asteroid reuse the same cited measurement. The detail page shows a Verified real-world longest axis field for every model record; it pre-fills the value and source wherever a defensible measurement is available. At this snapshot, 61 model records have a matched verified longest-axis value. Reported measurement uncertainty is shown where the cited publication provides it. Values are stored only where an explicit axis/extent or an authoritative maximum breadth is available; mean or equivalent diameters are not silently treated as longest axes. All other entries remain blank until a defensible, object-specific measurement can be sourced.
- Collection pages use three independent expandable dropdown sections: **Downloadable models**, **Sources**, and **Generators**. Search and source/type filters apply across all three sections. Generators are not mixed into source catalogues or counted as downloadable model files.
- Model detail pages show source credit, file format, file size, licence/use guidance and original download link where available.
- Printer fit checker with a Bambu Lab P2S profile (256 × 256 × 256 mm) and custom build-volume dimensions.
- Scale calculator for GLB previews: enter the real-world length of the model's longest axis and a scale denominator.
- Fit checks test all six axis-aligned 90° orientations.

## Important limitations

- Missing real-world dimensions, scale, licence or geometry are never guessed.
- NASA models are linked to the NASA 3D Resources repository; follow NASA's usage guidelines and attribution requirements.
- The fit checker uses the 3D preview's bounding box. It is not a slicer simulation and does not check wall thickness, supports, bed adhesion, brim, collision clearance or arbitrary-angle packing.
- STL and GLB files remain in their original formats when no native STEP file is provided. A mesh-to-STEP conversion is not presented as a proper CAD solid unless its quality is verified.
- STEP support varies by slicer: Bambu Studio and PrusaSlicer support STEP import, while UltiMaker Cura's documented model formats do not list STEP. STL remains the broadly compatible fallback.
- STL files are provided as direct downloads; the current in-browser preview and automatic geometry measurement are for GLB files only.
- Scaling recommendations use the measured model geometry and verified physical dimensions. The original source file is not modified; the selected scale can be exported as a binary STL in millimetres.
- NASA Solar System Treks generates files based on the selected world and area, so the archive links to the portal rather than pretending there is one fixed model file.
- The curated asteroid set links to original object pages rather than direct OBJ/PLY endpoints. The source confirms that model downloads are available on those pages; exact file names, variants and sizes remain on the source page and are not guessed in SPACEMESHER. The source site does not document an API. Wikimedia Commons documents a predictable media URL pattern but also notes that filenames and suffixes vary, so SPACEMESHER uses the source page until each direct endpoint can be verified. The 37 moon entries remain accessible through the source catalogue page.

## Automated real-world dimension research

A first Python research pipeline for the 256 curated numbered asteroids is available in `tools/dimensions/`. It queries the official JPL Small-Body Database API, accepts only exact numbered-object matches, and writes tri-/bi-axial `extent` results to the separate candidate file `data/real-world-dimension-candidates.json`. Effective diameters are recorded separately and are never treated as longest axes.

GitHub Actions can run the scanner weekly or manually. Existing verified dimensions are skipped. The scanner does not modify `data/real-world-dimensions.json`; candidate values must be reviewed before they can affect scale calculations. See [the dimension research guide](tools/dimensions/README.md).

## Run locally

Open `index.html` in a modern browser. No build step or package installation is required. The 3D preview uses Google's `model-viewer` web component loaded from a CDN.

## Data quality

Never infer a model's scale, dimensions, source or licence. Missing information should be shown as unknown until verified from the original source.


## Scaling & 3D Print workspace

The dedicated **Scaling & 3D Print** workspace is available from the top navigation and the bottom of the home page. Supported archive models expose a **Scaling** action in their detail view, which opens the workspace with the model file and any linked, verified real-world longest-axis measurement prefilled. The workspace also accepts local STL, OBJ, PLY and GLB uploads and displays an interactive 3D preview. Local uploads are processed in the browser and are not uploaded to SPACEMESHER.

The workspace supports millimetre, centimetre, metre and inch unit interpretation. External files also have an optional direct-diameter mode: enter the real object's original diameter and the desired printed diameter in millimetres to calculate the model scale without a verified longest-axis record. The collection breadcrumb uses “Asteroids & Comets” rather than the technical label “Small Bodies”. the GLB/glTF format uses metres by specification, while STL/OBJ/PLY units must be checked by the user. It calculates the source geometry dimensions, derives the original scale when a verified real-world reference is supplied, tests six axis-aligned 90° orientations against the selected printer volume, and suggests standard scale denominators. The built-in Bambu Lab P2S profile is 256 × 256 × 256 mm; custom build volumes can be entered. This is a bounding-box check, not a slicer simulation or a guarantee of printability. The source file is not modified. The selected printable scale can be exported directly as a binary STL in millimetres; the source file remains unchanged.

The reference-length helper accepts km, m, cm or mm and includes a guide for finding a defensible longest-axis measurement. It directs asteroids/comets to the JPL Small-Body Database `extent` field, planets/moons to NASA mission science pages or PDS shape-model records, and other cases to the original scientific publication/dataset. The guide explains how to select the largest axis, handle radii versus full dimensions, and record the exact source URL. A single effective/mean diameter, unsourced summary or model-file bounding box is not silently treated as a verified longest axis.

## Automatic object scaling

The Scaling workspace can identify asteroids and comets by name, number or designation, retrieve their measured `extent` axes from JPL SBDB, calculate the source model's original scale, and suggest familiar printable scale ratios based on the selected build volume. It deliberately does not substitute a single effective diameter for a longest physical axis.

A one-time Cloudflare Worker setup is required because the JPL API does not enable browser CORS. Follow [the proxy setup guide](cloudflare/README.md) and set the Worker URL in `config.js`. The Worker source is [cloudflare/jpl-proxy.js](cloudflare/jpl-proxy.js).
